2.2 Getters e setters: do jeito "Java" à propriedade C#

public class Pessoa
{
    // 1) Campo privado + métodos Get/Set (estilo Java)
    private string _cpf = string.Empty;
    public string GetCpf() { return _cpf; }
    public void SetCpf(string cpf)
    {
        if (cpf.Length != 11) throw new ArgumentException("CPF inválido");
        _cpf = cpf;
    }

    // 2) Propriedade AUTOMÁTICA: o compilador cria o campo escondido
    public string Nome { get; set; } = string.Empty;

    // 3) Propriedade COMPLETA, com validação no set ("value" = valor atribuído)
    private int _idade;
    public int Idade
    {
        get { return _idade; }
        set { if (value < 0) throw new ArgumentException("negativa"); _idade = value; }
    }

    // 4) Somente leitura, calculada
    public bool MaiorDeIdade => Idade >= 18;

    public Pessoa() { }                                         // construtor vazio
    public Pessoa(string nome, int idade) { Nome = nome; Idade = idade; } // sobrecarga

    public virtual string Apresentar() => $"Sou {Nome}";
}
// Três formas de criar objetos
Pessoa p1 = new Pessoa();  p1.Nome = "Ana";  p1.Idade = 17;
Pessoa p2 = new Pessoa("Bruno", 30);                   // construtor
Pessoa p3 = new Pessoa { Nome = "Carla", Idade = 25 };   // inicializador de objeto

2.4 Herança, polimorfismo e interface

public class Aluno : Pessoa                                   // herança
{
    public string Matricula { get; set; } = "";
    public Aluno(string n, int i, string m) : base(n, i) { Matricula = m; } // chama construtor da mãe
    public override string Apresentar() => base.Apresentar() + $" ({Matricula})";
}
public interface IAvaliador { double Avaliar(Aluno a); }
public class Professor : Pessoa, IAvaliador { ... }           // 1 classe mãe + N interfaces

List<Pessoa> pessoas = new() { new Pessoa(...), new Aluno(...) };
foreach (var p in pessoas) Console.WriteLine(p.Apresentar()); // polimorfismo
LembreC# tem herança simples de classes (só uma mãe) e pode implementar várias interfaces. Só dá para usar override em método marcado virtual ou abstract na mãe. Toda classe herda de object (por isso existe ToString()).

2.5 Relacionamento entre classes

  • Associação / composição ("tem um"): public Professor? Professor { get; set; }
  • 1 para N ("tem vários"): public List<Aluno> Alunos { get; set; } = new();
  • Herança ("é um"): Aluno : Pessoa
public class Turma
{
    public Professor? Professor { get; set; }
    public List<Aluno> Alunos { get; set; } = new();
    public void Matricular(Aluno a) { if (!Alunos.Any(x => x.Matricula == a.Matricula)) Alunos.Add(a); }
}
Referência × valorClasses são tipos por referência: Pessoa b = a; copia só o endereço, então mudar b.Nome muda a.Nome. int, double, bool, char e struct são por valor (a atribuição copia o valor).

3. Como a Web funciona: HTTP, REST e JSON

3.1 Cliente-servidor

O cliente (navegador, app, Postman, REST Client) envia uma requisição. O servidor (a nossa API) processa e devolve uma resposta. O HTTP é sem estado (stateless): cada requisição é independente.

Requisição tem
  • Método HTTP (GET, POST...)
  • URL (endereço/rota)
  • Cabeçalhos (ex.: Content-Type: application/json)
  • Opcional: corpo (JSON) ou parâmetros na URL
Resposta tem
  • Código de status HTTP (200, 404...)
  • Cabeçalhos
  • Corpo: o dado, informação ou mensagem

Essa divisão aparece nos comentários do Program.cs da aula: "Requisições: método HTTP, URL, opcional corpo/parâmetros de URL. Resposta: dado/informação/mensagem, código de status HTTP".

3.2 Anatomia de uma URL

3.5 REST e API

  • API (Application Programming Interface): um conjunto de endpoints que outro programa (o front-end em React, por exemplo) consome.
  • Web API: API acessada por HTTP.
  • REST (Representational State Transfer): estilo de arquitetura em que tudo é recurso identificado por URL (/api/produto), manipulado pelos verbos HTTP, com comunicação sem estado e representação geralmente em JSON. Uma API que segue isso é chamada de RESTful.
  • Endpoint: a combinação método + rota que executa uma funcionalidade. GET /api/produto/listar e POST /api/produto/cadastrar são endpoints diferentes.

3.6 JSON

JSON (JavaScript Object Notation) é um formato de texto para trocar dados. Tem objetos { } com pares "chave": valor, listas [ ], strings entre aspas duplas, números, true/false e null.

{
  "id": "1d27...bd19",
  "nome": "Mouse",
  "preco": 50,
  "quantidade": 10,
  "criadoEm": "2026-09-28T13:02:41"
}

Serialização: objeto C# → JSON (na resposta). Desserialização: JSON → objeto C# (o corpo do POST vira um Produto).

O ASP.NET faz isso sozinho (System.Text.Json). As propriedades em PascalCase do C# (Nome) viram camelCase no JSON (nome), e a leitura não diferencia maiúsculas de minúsculas.

4. Minimal APIs no ASP.NET Core

4.1 O que é

ASP.NET Core é o framework web do .NET. As Minimal APIs declaram endpoints direto no Program.cs com app.MapGet/MapPost/... e uma lambda, sem precisar de Controllers (o modelo MVC/Web API "tradicional"). O projeto é criado com dotnet new web.

4.2 Esqueleto

var builder = WebApplication.CreateBuilder(args); // 1. configura: serviços, DI, config
// builder.Services.AddDbContext<AppDataContext>();  (registrar serviços AQUI)
var app = builder.Build();                         // 2. constrói a aplicação

app.MapGet("/", () => "API do Ecommerce");        // 3. mapeia endpoints

app.Run();                                          // 4. sobe o servidor (bloqueia; o que vier depois não roda)

4.5 Retornos: a classe Results

O endpoint devolve um IResult com status e corpo: Results.Ok(obj) → 200, Results.Created(url, obj) → 201, Results.NoContent() → 204, Results.BadRequest(msg) → 400, Results.NotFound(msg) → 404, Results.Conflict(msg) → 409. Se a lambda devolve uma string simples, sai 200 com texto puro. Se devolve um objeto, sai 200 com JSON.

PegadinhaQuando a lambda tem vários return, todos precisam devolver Results.X(...) (o mesmo tipo IResult). Misturar return produtos; com return Results.NotFound() não compila.

5. Código da aula comentado + CRUD completo

5.1 Modelo

public class Produto
{
    public string Id { get; set; } = Guid.NewGuid().ToString(); // id único gerado ao criar o objeto
    public string Nome { get; set; } = String.Empty;
    public DateTime CriadoEm { get; set; } = DateTime.Now;     // data/hora da criação
}

GUID (Globally Unique Identifier) é um identificador de 128 bits, praticamente impossível de repetir, por exemplo 1d274707-7f49-45f1-a066-f34c3697bd19. Os valores depois do = são inicializadores de propriedade: rodam em todo new Produto(), inclusive quando o JSON é desserializado.

5.2 Endpoints da aula (GET e POST), explicados

List<Produto> produtos = new List<Produto>();   // "banco" EM MEMÓRIA: some quando a API para

app.MapGet("/api/produto/listar", () =>
{
    if (produtos.Count == 0) return Results.BadRequest("A lista de produtos está vazia");
    return Results.Ok(produtos);                    // 200 + JSON da lista
});

app.MapPost("/api/produto/cadastrar", (Produto? produto) =>   // vem do CORPO (JSON)
{
    if (produto is null) return Results.BadRequest("O produto não pode ser nulo");
    if (produto.Nome == "") return Results.BadRequest("O nome não pode ser vazio");
    foreach (Produto cadastrado in produtos)        // regra: nome único
        if (cadastrado.Nome == produto.Nome) return Results.BadRequest("Já existe um produto com o mesmo nome");
    produtos.Add(produto);
    return Results.Created("", produto);           // 201 Created
});

app.MapGet("/api/produto/buscar/{nome}", (string nome) =>   // vem da ROTA
{
    foreach (Produto cadastrado in produtos)
        if (cadastrado.Nome == nome) return Results.Ok(cadastrado);
    return Results.NotFound("Produto não encontrado!"); // 404
});

5.3 Exercício da aula resolvido: remoção e alteração

//DELETE: /api/produto/remover/{id}
app.MapDelete("/api/produto/remover/{id}", (string id) =>
{
    Produto? resultado = produtos.FirstOrDefault(p => p.Id == id);  // LINQ no lugar do foreach
    if (resultado is null) return Results.NotFound("Produto não encontrado!");
    produtos.Remove(resultado);
    return Results.Ok(resultado);
});

//PUT: /api/produto/alterar/{id}  (id na ROTA + dados novos no CORPO)
app.MapPut("/api/produto/alterar/{id}", (string id, Produto produtoAlterado) =>
{
    Produto? resultado = produtos.FirstOrDefault(p => p.Id == id);
    if (resultado is null) return Results.NotFound("Produto não encontrado!");
    resultado.Nome = produtoAlterado.Nome;          // Id e CriadoEm continuam os mesmos
    resultado.Preco = produtoAlterado.Preco;
    resultado.Quantidade = produtoAlterado.Quantidade;
    return Results.Ok(resultado);
});

//PATCH: /api/produto/estoque/{id}?quantidade=20  (altera SÓ um campo)
app.MapPatch("/api/produto/estoque/{id}", (string id, int quantidade) =>
{
    Produto? resultado = produtos.FirstOrDefault(p => p.Id == id);
    if (resultado is null) return Results.NotFound("Produto não encontrado!");
    resultado.Quantidade = quantidade;
    return Results.Ok(resultado);
});
Por que FirstOrDefault funciona para alterar?Ele devolve a referência do objeto que está dentro da lista. Alterar resultado.Nome altera o objeto guardado na lista (tipo por referência, §2.5). Por isso não é preciso "salvar de volta".

Por que usar o Id e não o nome para alterar ou remover? Porque o nome pode mudar (é justamente o que o PUT altera) e o Id é o identificador estável e único do recurso.

6. Entity Framework Core (persistência)

6.1 Conceitos

  • Persistência: guardar os dados de forma que sobrevivam ao fim do programa. A List em memória some quando a API para. O banco de dados não.
  • ORM (Object-Relational Mapping, mapeamento objeto-relacional): converte automaticamente entre objetos C# e tabelas/linhas do banco relacional. Classe → tabela. Propriedade → coluna. Objeto → linha. Você escreve LINQ e o ORM gera o SQL.
  • Entity Framework Core (EF Core): o ORM oficial do .NET. Funciona com vários bancos por meio de providers (SQLite, SQL Server, MySQL, PostgreSQL).
  • SQLite: banco que fica num arquivo local (Ecommerce.db), sem servidor para instalar. Bom para estudo.
  • Code First: você escreve as classes primeiro e o EF gera o banco a partir delas (via migrations).

6.2 Passo a passo

  1. Instalar os pacotes NuGet no projeto: 
    dotnet add package Microsoft.EntityFrameworkCore.Sqlite    # provider do banco
dotnet add package Microsoft.EntityFrameworkCore.Design    # necessário para migrations
dotnet tool install --global dotnet-ef                     # ferramenta de linha de comando (uma vez)
  2. Criar o contexto (herda de DbContext): 
    using Microsoft.EntityFrameworkCore;
public class AppDataContext : DbContext
{
    public DbSet<Produto> Produtos { get; set; }     // cada DbSet = uma TABELA
    public DbSet<Categoria> Categorias { get; set; }
    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    {
        optionsBuilder.UseSqlite("Data Source=Ecommerce.db");  // connection string
    }
}
  3. Registrar no Program.cs (injeção de dependência): builder.Services.AddDbContext<AppDataContext>(); (antes do builder.Build()).
  4. Gerar e aplicar a migration (dentro da pasta do projeto): 
    dotnet ef migrations add InicialCriacaoTabelas   # gera a pasta Migrations/ com o código C# que cria as tabelas
dotnet ef database update                        # executa no banco: cria o Ecommerce.db e as tabelas
  5. Receber o contexto no endpoint: ([FromServices] AppDataContext ctx) => ...
MigrationÉ o "controle de versão" do esquema do banco. Sempre que mudar uma classe (nova propriedade, nova entidade), rode migrations add NovoNome e depois database update. A tabela __EFMigrationsHistory registra quais migrations já foram aplicadas. dotnet ef migrations remove desfaz a última que ainda não foi aplicada.

6.4 Endpoint completo com EF

app.MapPost("/api/produto/cadastrar", ([FromBody] Produto produto, [FromServices] AppDataContext ctx) =>
{
    if (ctx.Produtos.Any(p => p.Nome == produto.Nome))
        return Results.Conflict("Já existe um produto com o mesmo nome");
    ctx.Produtos.Add(produto);
    ctx.SaveChanges();
    return Results.Created($"/api/produto/buscar/{produto.Id}", produto);
});

app.MapDelete("/api/produto/remover/{id}", ([FromRoute] string id, [FromServices] AppDataContext ctx) =>
{
    Produto? produto = ctx.Produtos.Find(id);
    if (produto is null) return Results.NotFound("Produto não encontrado!");
    ctx.Produtos.Remove(produto);
    ctx.SaveChanges();
    return Results.Ok(produto);
});

6.5 Convenções e Data Annotations

  • Uma propriedade chamada Id ou <Classe>Id vira a chave primária automaticamente (ou use [Key]).
  • Relacionamento 1:N: public string? CategoriaId { get; set; } (chave estrangeira) + public Categoria? Categoria { get; set; } (propriedade de navegação).
  • Tipos anuláveis (string?) viram colunas que aceitam NULL.
using System.ComponentModel.DataAnnotations;
public class Produto
{
    [Key] public string Id { get; set; } = Guid.NewGuid().ToString();
    [Required(ErrorMessage = "O nome é obrigatório")]
    [MinLength(3)] [StringLength(100)]         // StringLength/MaxLength também limitam a coluna
    public string Nome { get; set; } = "";
    [Range(0.01, 100000)] public double Preco { get; set; }
    [EmailAddress] public string? EmailFornecedor { get; set; }
}

Outras annotations: [MaxLength], [RegularExpression], [Compare], [Phone], [NotMapped] (não vira coluna), [Table("Nome")], [Column("nome")].

Minimal API não valida sozinha (.NET 8)Nos Controllers com [ApiController] a validação é automática. Na Minimal API do .NET 8 é preciso validar manualmente: 
List<ValidationResult> erros = new();
if (!Validator.TryValidateObject(produto, new ValidationContext(produto), erros, true))
    return Results.BadRequest(erros);   // 400 com a lista de mensagens

6.6 Injeção de dependência (DI)

Em vez de o endpoint criar o próprio new AppDataContext(), ele recebe um pronto do framework. O AddDbContext registra o contexto com tempo de vida Scoped: uma instância por requisição HTTP, descartada no final. Isso desacopla o código e facilita testes. Tempos de vida: Singleton (uma instância para sempre), Scoped (uma por requisição), Transient (uma nova a cada pedido).

7. Lista de exercícios: ordenação (Exe06)

Enunciado: gerar um vetor com 100 números aleatórios e ordená-lo, (a) manualmente e (b) com recurso da linguagem.

int[] vetor = new int[100];
Random random = new Random();
for (int i = 0; i < vetor.Length; i++) vetor[i] = random.Next(1000);

// (a) BUBBLE SORT: compara vizinhos e troca se estiverem fora de ordem
bool troca;
do
{
    troca = false;
    for (int i = 0; i < vetor.Length - 1; i++)   // -1 porque acessa vetor[i + 1]
    {
        if (vetor[i] > vetor[i + 1])
        {
            troca = true;
            int aux = vetor[i];                     // troca com variável auxiliar
            vetor[i] = vetor[i + 1];
            vetor[i + 1] = aux;
        }
    }
} while (troca);                                  // repete até uma passada sem trocas

// (b) Exe06b: recurso pronto
Array.Sort(vetor);
Erro comum (estava na versão do zip)Só um for, sem o do-while: uma passada leva o maior elemento para o final, mas o vetor não fica ordenado. É preciso repetir as passadas (no pior caso, n−1 vezes). Complexidade do Bubble Sort: O(n²). Array.Sort: O(n log n).

Teste de mesa de uma passada em [5, 1, 4, 2]: troca 5↔1 → [1,5,4,2]. Troca 5↔4 → [1,4,5,2]. Troca 5↔2 → [1,4,2,5] (houve troca, então repete). Segunda passada → [1,2,4,5]. Terceira passada: nenhuma troca, fim.

9. Pegadinhas de prova

  1. 17 / 5 dá 3 (divisão inteira). Use 17 / 5.0 ou um cast.
  2. = é atribuição. == é comparação.
  3. Vetor usa .Length. Lista usa .Count. String usa .Length.
  4. random.Next(1000) vai até 999. O limite superior é exclusivo.
  5. for (i = 0; i <= v.Length; i++) estoura o vetor. O certo é <.
  6. O construtor não tem tipo de retorno (nem void) e tem o mesmo nome da classe.
  7. Sem virtual na mãe, não há override.
  8. Criar um objeto de uma classe abstract ou de uma interface com new não é permitido.
  9. POST não é idempotente. PUT substitui tudo. PATCH altera parte.
  10. 404 = recurso não encontrado (erro do cliente). 500 = erro no servidor. 400 = requisição inválida. 201 = criado.
  11. No .http falta a linha em branco antes do corpo, ou o Content-Type: application/json, e o corpo chega nulo.
  12. Código depois de app.Run() não executa (enquanto a API estiver rodando). Serviços são registrados antes do builder.Build().
  13. Esquecer ctx.SaveChanges(): nada é gravado.
  14. Mudou o modelo e não rodou migrations add + database update: erro "no such column/table".
  15. Find só busca pela chave primária. Para outros campos, use FirstOrDefault/Where.
  16. FirstOrDefault devolve null quando não acha, então sempre cheque is null antes de usar.
  17. LINQ tem execução adiada: a consulta só roda no ToList(), First(), Count() etc.
  18. Os dados em List na memória somem quando a API reinicia. Por isso existe o EF/banco.

Objetivas

1. Qual método HTTP é o mais indicado para cadastrar um novo produto?
a) GET b) POST c) PUT d) DELETE
b) POST. Cria um recurso novo e responde 201 Created.
2. Uma API responde 404. Isso significa:
a) sucesso sem conteúdo b) erro interno do servidor c) recurso não encontrado d) requisição criada
c) 404 Not Found (erro do cliente, faixa 4xx).

PUT substitui o recurso inteiro (manda todos os campos). PATCH altera parcialmente (só os campos enviados).

4. 7/2 = 3 (divisão inteira) e 7%2 = 1.
6. O que acontece se você chamar ctx.Produtos.Add(p) e não chamar ctx.SaveChanges()?
O produto só fica marcado no change tracker. Nenhum INSERT é executado e nada é gravado no banco.

Polimorfismo (método virtual na mãe e override na filha).

b). O a) aplica as migrations no banco.
9. O que é um ORM?
Mapeamento objeto-relacional: uma camada que converte automaticamente objetos/classes em linhas/tabelas de um banco relacional e gera o SQL (ex.: Entity Framework Core).
10. Qual status deve retornar um cadastro bem-sucedido, e qual método de Results o produz?
201 Created, com Results.Created(url, objeto).

16. Modele: uma Categoria tem vários Produtos. Como fica no EF?
Em Produto: public string? CategoriaId { get; set; } (FK) e public Categoria? Categoria { get; set; } (navegação). No contexto: DbSet<Categoria> Categorias. Para trazer junto: ctx.Produtos.Include(p => p.Categoria). Depois, migrations add + database update.
17. Por que a API em memória perde os dados e como o EF resolve?
A List<Produto> vive na RAM do processo e some quando a API para. O EF grava num banco (arquivo SQLite, por exemplo), que persiste entre execuções.

11. Folha de cola final

// ===== Program.cs de uma Minimal API com EF =====
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<AppDataContext>();
var app = builder.Build();

app.MapGet("/api/produto/listar", ([FromServices] AppDataContext ctx) =>
    ctx.Produtos.Any() ? Results.Ok(ctx.Produtos.ToList()) : Results.NotFound("Vazio"));

app.MapGet("/api/produto/buscar/{id}", ([FromRoute] string id, [FromServices] AppDataContext ctx) =>
    ctx.Produtos.Find(id) is Produto p ? Results.Ok(p) : Results.NotFound());

app.MapPost("/api/produto/cadastrar", ([FromBody] Produto p, [FromServices] AppDataContext ctx) =>
{ ctx.Produtos.Add(p); ctx.SaveChanges(); return Results.Created($"/api/produto/buscar/{p.Id}", p); });

app.MapPut("/api/produto/alterar/{id}", ([FromRoute] string id, [FromBody] Produto novo, [FromServices] AppDataContext ctx) =>
{
    Produto? p = ctx.Produtos.Find(id);
    if (p is null) return Results.NotFound();
    p.Nome = novo.Nome; p.Preco = novo.Preco; p.Quantidade = novo.Quantidade;
    ctx.Produtos.Update(p); ctx.SaveChanges(); return Results.Ok(p);
});

app.MapDelete("/api/produto/remover/{id}", ([FromRoute] string id, [FromServices] AppDataContext ctx) =>
{
    Produto? p = ctx.Produtos.Find(id);
    if (p is null) return Results.NotFound();
    ctx.Produtos.Remove(p); ctx.SaveChanges(); return Results.Ok(p);
});

app.Run();
